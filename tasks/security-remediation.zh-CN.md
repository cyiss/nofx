## 升级现有实例

- **先备份数据库和现有加密密钥。** AES 示例密钥现被拒绝；若旧数据库实际用该密钥加密，需离线解密并迁移，或在安全备份后重新导入凭证。直接换密钥会导致旧数据无法解密。修复不会自动旋转密钥。
- 数据库新增 `session_version`。新版本每次鉴权查询账户版本；改密/重置/登出会撤销该账户所有旧会话，包括其他设备。旧 JWT 缺少该字段视为版本 0，升级本身不会强制登出所有人；需要立即撤销时修改密码或执行登出。
- 新钱包不再复制到 `.env`。历史 `.env` 中的明文私钥不会自动删除：确认数据库内归属正确且有安全备份后，再人工清理历史副本及不必要的环境变量。
- 本机 API 默认 `127.0.0.1`；容器内设置 `API_SERVER_HOST=0.0.0.0`，主机映射仍绑定 `127.0.0.1`。远程入口需配置 HTTPS 反向代理。未信任代理时，代理后的客户端共享代理 IP 限流桶。
- Railway 必须持久配置 JWT、AES、RSA 密钥；缺失即启动失败，不再每次重启生成新密钥。健康检查连到后端，任一进程退出会停止另一进程。
- 安装使用本地完整 checkout 中的 `sh install.sh`（会构建并启动）。本次验证只运行了模拟安装，没有执行实际部署。
- 付款结算状态不明时先核对付款服务/链上结果，不应盲目手工重试。风险检查拒绝开仓也不代表已有仓位已平仓。

这些修改针对已识别问题；未进行真实交易、付款或公网攻击测试，也不能据此保证项目绝对安全。
